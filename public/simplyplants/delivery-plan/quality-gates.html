Quality Gates & Validation Checklist

SimplyPlants PLP Filter Architecture

This document defines mandatory quality gates that must be satisfied before phase transitions and final launch. Gates enforce evidence-based validation and prevent defect leakage.

Environment Validation

  • ⬜ All 8 Docker containers running (phpfpm, db, opensearch, valkey, rabbitmq, mailcatcher, phpmyadmin, proxy)
  • ⬜ Homepage loads at https://simplyplants.local:9443 in <3s with zero console errors
  • ⬜ Hyva theme active and rendering TailwindCSS + Alpine.js
  • ⬜ OpenSearch health check green in Magento admin
  • ⬜ Playwright E2E framework functional (sample test passing)
  • ⬜ Tailwind CSS builds successfully inside Docker container
  • ⬜ Static content clears without errors

Evidence Required: env-validation-report.md, screenshots/homepage-baseline.png, test-results/env-validation/

Module Scaffolding

  • ⬜ SimplyPlants_PlpFilter module registered and enabled
  • ⬜ Module appears in admin: Stores > Configuration > Advanced > Advanced
  • ⬜ PHPCS passes with Magento2 standard (zero violations)
  • ⬜ Module structure follows Magento 2 best practices

Evidence Required: make magento module:status output, PHPCS report

Database Schema

  • ⬜ 3 tables created: simplyplantsfiltercode, simplyplantscategoryfacet, simplyplants_hotkey
  • ⬜ All indexes and foreign keys applied correctly
  • ⬜ db_schema.xml validates against Magento XSD
  • ⬜ 133 filter codes populated (SELECT COUNT(*) = 133)
  • ⬜ 480 facet configs populated (30 categories × 16 attributes)
  • ⬜ 12 hot keys populated with valid JSON
  • ⬜ Data patches idempotent (safe to re-run)

Evidence Required: MySQL table dumps, data-verification-report.md, ERD diagram

Repository Layer

  • ⬜ 3 repository interfaces defined with SearchCriteria support
  • ⬜ 3 repository implementations with proper exception handling
  • ⬜ Unit tests achieve >80% code coverage on repositories
  • ⬜ PHPStan level 8 passes on Model/ and Api/ directories
  • ⬜ di.xml preferences configured for all interfaces

Evidence Required: PHPUnit coverage report, PHPStan output

Technical Specifications

  • ⬜ 7 specification documents complete (ARCHITECTURE, URL-ROUTING-SPEC, FACET-ENGINE-SPEC, HOT-KEYS-SPEC, SEO-SPEC, BADGE-SPEC, API-CONTRACTS)
  • ⬜ Each spec includes Given/When/Then acceptance criteria
  • ⬜ Each spec includes 5+ examples with real filter codes
  • ⬜ Each spec includes edge cases and error handling
  • ⬜ Sequence diagrams created for key flows (filter application, category change, hot key)
  • ⬜ Product owner reviews and approves all specifications

Evidence Required: Complete docs/ directory with 7 spec files, approval email/sign-off

Gate Owner: Development Team

Gate Approval Required From: Product Owner

Failure Action: Do not proceed to P1 until all checks pass

Category Taxonomy

  • ⬜ 30 categories created (16 L1 + 30 L2 sub-categories)
  • ⬜ All category URL keys match filter codes from registry
  • ⬜ All categories set to Is Active = Yes
  • ⬜ All categories assigned to Default store view
  • ⬜ URL rewrites table contains entries for all 30 categories
  • ⬜ All category URLs resolve on frontend (no 404s)

Evidence Required: Admin screenshot, category-export.csv, frontend URL test results

Custom Router

  • ⬜ Router registered in di.xml with sortOrder=25 (before standard router)
  • ⬜ Router intercepts /plants/* requests successfully
  • ⬜ Invalid URLs (e.g., /plants/invalid) return 404 (not intercepted)
  • ⬜ Router match() performance <5ms per request
  • ⬜ Unit tests cover 20+ slug parsing scenarios
  • ⬜ Integration tests verify routing for 10+ URL patterns

Evidence Required: Router code, unit test report, integration test results, performance benchmark

  • ⬜ SlugGenerator expands hot keys to constituent filter codes
  • ⬜ SlugGenerator caches results in Redis (verified cache hits)
